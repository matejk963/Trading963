# MKTT refactor — Gap & Code Review findings

Generated 2026-06-12 by a 4-agent read-only review (2 gap-vs-original, 2 code-review). **34 findings** — 8 high, 14 medium, 12 low.


## 🐞 Bugs (correctness)  (7)

- **[HIGH] Options drilldown route ignores the strike — per-contract drilldown is a no-op** — _Options_
  - Original /api/options/drilldown returned the individual contracts behind a clicked strike (expiration/side/OI/IV/gamma/GEX rows) via a dedicated drilldown implementation, surfaced by clicking a bar or table row (templates/options.html:218-220,252-275). The new route options_drilldown_api parses the SAME OptionsRequest and calls the SAME handle, which never reads request.args['strike'] — it recomputes and returns the full GEX profile envelope (options/routes.py:57-62; service.handle has no strike concept). The route's own docstring concedes 'strike is echoed into meta.context' but from_query never parses strike, so even the echo is absent. Net: drilldown returns the whole profile regardless of strike, and no front-end calls it anyway (no click handler in options.html / viewmodel.js). The per-contract breakdown feature is gone.
  - `src/mktt/sections/options/routes.py:57-62; src/mktt/sections/options/service.py:60-90 (from_query / handle, no strike); original src/mktt/templates/options.html:252-275`
  - **Fix:** Either implement a real drilldown (parse strike, return the per-contract rows from the chain) and wire a click handler in options.html, or remove the dead route and document the loss.
- **[HIGH] rs_rank cross-sectional over only the Writer stale subset not the full universe** — _computed/writer + kernel/relative_strength_
  - Writer.run ranks via relative_strength.rank(panel, by returns_6m) on exactly the ids passed to run (writer.py 97,105); rank ranks per date across only those symbols (relative_strength.py 151). Legacy ranks across the entire universe (stage_classifier.py 101-102). For a stale subset rs_rank becomes a percentile within the subset, and stage.compute thresholds on rs_rank (stage.py 118,127,133,141) so stages silently change. pca_regime recomputes rs_rank over the same subset wide panel (pca_regime.py 105).
  - `src/mktt/computed/writer.py:97-109; relative_strength.py:131-153; pca_regime.py:105`
  - **Fix:** rs_rank is universe-wide; rank over the full universe while writing only stale rows, or enforce run always gets the complete universe.
- **[MEDIUM] Pool maxconn=10 can be exhausted under concurrent slow renders -> 500** — _app.py factory / pool_
  - build_pooled_conn_factory uses ThreadedConnectionPool(min=0, max=10) (app.py:83-102,184). app.run(debug=True) serves threaded, and a single screener render holds connections while doing a multi-second fundamentals + cross_section read. Under a handful of concurrent requests (or a few browser tabs) getconn() raises psycopg2.pool.PoolError('connection pool exhausted'), which propagates out of the store _query (no catch) and 500s the route — routes have no try/except, so provider/DB failures surface as 500 rather than an error ViewModel. Connections themselves are correctly returned (finally: conn.close() -> putconn, even on exception), so this is exhaustion, not a leak.
  - `src/mktt/app.py:96,184; src/mktt/computed/store.py:131-141`
  - **Fix:** Raise maxconn (or make it env-configurable) to comfortably exceed expected concurrency, and wrap the store reads / route handlers so a PoolError/DB error returns vm(status='error', ...) instead of a bare 500. Consider blocking getconn or a bounded retry.
- **[MEDIUM] Live turnover (ADV) semantics diverge from the original turnover gate** — _screener parity_
  - The min_turnover gate now compares against ADV_Dollar = last close * mean(volume over last 50 bars) computed live (service.py:604-608, 692-693). The original gated on uni_row['turnover'] from the prebuilt universe file (git d147da2~1:app.py:~407). If volume.parquet is missing/sparse for a symbol, ADV_Dollar stays None -> turnover coerces to 0.0 -> the symbol is dropped by the default min_turnover=500000, even though it has valid price/classification data. This can silently shrink the universe versus the original for any symbol lacking recent volume.
  - `src/mktt/sections/screener/service.py:604-608, 692-694`
  - **Fix:** Confirm volume.parquet coverage matches close.parquet; fall back to the precomputed ADV_Dollar carried on the cross-section (already supported via pass-through) when live volume is unavailable, rather than treating missing ADV as 0 and filtering the row out.
- **[LOW] Dist to 52w High sort maps to From52H ascending, inverting the original ranking** — _Screener sort_
  - Original dist_high sort used Dist52wHigh percent ascending (a positive distance, nearest-high first). New SORT_COLUMNS maps dist_high to From52H ascending (service.py:98); From52H is computed as (price/high-1)*100, i.e. at most 0, so ascending surfaces the farthest-below-high (most negative) first, the inverse of closest-to-52w-high.
  - `src/mktt/sections/screener/service.py:98,613; cf. app.py:303`
  - **Fix:** Sort From52H descending (closest-to-zero first) for the dist_high option, or derive a positive distance column matching the original semantics.
- **[LOW] Lazy _providers() singletons are built without a lock (benign race) and never reset on stale state** — _routes (all sections)_
  - Every section's _providers() does an unsynchronized check-then-build on a module-level _PROVIDERS dict (screener/routes.py:28-40, monitor/routes.py:33-54, options/rrg/macro identical). Under threaded serving two concurrent first-hits can each build a DataSource/ComputedStore (the factory pre-seeds them via _inject_shared_providers so in production this is usually avoided, but the API routes can still trigger it if injection is bypassed). Worst case is duplicate construction (extra connections), not corruption. Also note _inject_shared_providers only overwrites 'computed'/'lists' when the key already exists (app.py:145-148) — correct today, but silently no-ops if a section's _PROVIDERS keys ever drift.
  - `src/mktt/sections/screener/routes.py:28-40; src/mktt/app.py:144-148`
  - **Fix:** Guard the lazy build with a lock, or rely solely on factory injection and assert the providers are present at first request. Add a test that every key _inject_shared_providers writes actually exists in each section's _PROVIDERS.
- **[LOW] Sector-map summary writes server JSON into innerHTML without escaping** — _screener template (innerHTML)_
  - The section screener.html data table is safe (Jinja autoescape, no |safe), and viewmodel.js renders all cells via textContent (static/js/viewmodel.js:78-98) — no XSS there. However the legacy app-level templates/screener.html injects fetched API content into innerHTML, e.g. document.getElementById('map-summary').innerHTML = '...'+data.error+'...' and member.innerHTML = '<strong>'+m.sym+'</strong> ... '+m.industry (templates/screener.html:830,1021,1408). If those endpoints (sector_map / drilldown) are reachable and any field is attacker-influenced this is a DOM-XSS sink. The section shell that the ChoiceLoader actually serves does not contain these sinks, so impact depends on whether the legacy template is still routed.
  - `src/mktt/templates/screener.html:830,1021,1408`
  - **Fix:** Confirm the legacy templates/screener.html is fully superseded (the ChoiceLoader prioritizes the section copy); if any legacy template/endpoint is still served, switch these innerHTML assignments to textContent / DOM building as viewmodel.js already does.

## ⚡ Efficiency  (3)

- **[HIGH] upsert reupserts the entire history about 6.5M rows every run via iterrows** — _computed/store.upsert_
  - upsert loops the whole panel with iterrows (store.py 298-304) then execute_values INSERT ON CONFLICT over all rows (store.py 331-347). With 6.5M rows iterrows is the slowest iteration and ON CONFLICT rewrites every history row though history is append-only by date PK.
  - `src/mktt/computed/store.py:298-304, 331-347`
  - **Fix:** Replace iterrows with itertuples; write only rows newer than each symbol stored MAX(date) via last_bar_dates (store.py 224-238).
- **[HIGH] Per-request full-universe time_series reassembled in a Python per-symbol loop (the 6-7s cliff)** — _screener / datasource_
  - _apply_live_technicals fetches a 420-day panel over the whole ~4835-symbol universe every request (service.py:542-562). data.time_series -> EquitySubmodule._universe_frames loops PER SYMBOL building a tiny per-field DataFrame and a per-symbol MultiIndex frame, then pd.concat over thousands of frames (equity.py:153-217); _derive_panel_technicals then groupby(level='symbol') again (service.py:581-618). Only the raw parquet read is mtime-cached (equity.py:94-105) — the per-symbol assembly + concat + groupby is rebuilt every request. The ORIGINAL did this vectorized over a single cached close panel (close.rolling(50).mean(), close.iloc[-252:].max(), etc. — git d147da2~1:app.py:360-430) with no per-symbol Python loop. This is the dominant cost behind the logged ~6-7s render (log item c).
  - `src/mktt/datasource/submodules/equity.py:153-217; src/mktt/sections/screener/service.py:542-618`
  - **Fix:** Compute technicals vectorized straight off the wide parquet panels (Price=last close, From52H/From52L from rolling max/min over columns, ADV=price*volume.tail(50).mean()) instead of materializing per-symbol frames; and/or memoize the derived-technicals dict keyed by the parquet mtimes so repeat page loads within a data epoch are O(1).
- **[MEDIUM] cross_section() re-runs a full-table SQL on every call and is never cached** — _screener / monitor / computed_
  - ComputedStore.cross_section() issues a fresh DISTINCT ON SQL over classification_current (~4835 rows) and builds a DataFrame on every invocation (computed/store.py:146-176) with no in-memory cache. The screener page calls it once per request; monitor._handle_multi calls it to look up rs_rank for a handful of symbols, materializing the entire cross-section each POST (monitor/service.py:345). Combined with the per-request fundamentals + time_series reads, each screener render does three full-universe round-trips.
  - `src/mktt/computed/store.py:146-176; src/mktt/sections/monitor/service.py:345`
  - **Fix:** Add a short-TTL / mtime-or-asof-keyed cache for cross_section() (it is one-row-per-symbol and changes only on a Writer run). For monitor multi, query rs_rank by symbol list (cross_section(filters=...) or a targeted WHERE symbol = ANY) instead of pulling the whole table.

## 1. The 6 layers (where everything lives)

### 🎛️ Controllers & Routes — *the HTTP layer*
- **`app.py`** ⚠️ **complex, 2090 lines, fan-out 7 — THE refactor target.** Builds the app, registers the macro blueprint, and defines *every* top-level page route + JSON API (screener, options/GEX, watchlist, charts, fundamentals, EPS). Also loads PCA/stage/Refinitiv classification lookups. Most business logic is tangled in here.
- **`macro/__init__.py`** — Flask Blueprint (`url_prefix=/macro`); imports `routes`. *This is the pattern to copy.*
- **`macro/routes.py`** — thin macro handlers (liquidity, layer-detail, overlay, transmission, RRG + drilldown) that **delegate to services**. The clean controller other features lack.

### 🧠 Domain & Business Logic — *the analytics engines*
- **`screener.py`** (moderate) — Yahoo screener API + on-disk cache; `available-sectors` helper. *Note: the heavy `screener_page` orchestration still lives in `app.py` — it belongs here.*
- **`stage_classifier.py`** ⚠️ complex, **fan-in 6** — vectorized Weinstein stages (MA/RS-line/distribution features → Stage 1-4). Clean entry `run_stage_from_local_db` + module TTL cache. *Good packaging model.*
- **`gex_engine.py`** ⚠️ complex — **pure-math** GEX (Black-Scholes gamma, strike aggregation, gamma-flip, call/put walls). Stateless.
- **`options_service.py`** ⚠️ complex — I/O orchestration (yfinance chains+spot, caching, rate-limit backoff) → delegates math to `gex_engine`. **Cleanest seam in the app.**
- **`macro/liquidity_service.py`** ⚠️ complex — liquidity regime/layer scores/overlays/transmission → Plotly payloads.
- **`macro/rrg_service.py`** ⚠️ complex — RRG RS-ratio/momentum tails → Plotly traces + tables + drilldown.

### 💾 Data Access & Pipelines — *market data + batch jobs*
- **`data_manager.py`** ⚠️ complex, **fan-in 7 (most depended-on)** — yfinance universe + OHLCV → parquet; cached loaders. **Stable contract to preserve: `load_prices` / `load_universe` / `load_spy`.**
- **`data_freshness.py`** ⚠️ complex — staleness audit of price/Refinitiv/universe/classification files; powers `/api/freshness`. *Your observability hook — extend with debug logging here.*
- **`update_classifications.py`** ⚠️ complex, fan-out 6 — **offline batch** regenerating classification JSON (stages, PCA clusters, MA screener, EPS accel). Web layer reads its output at request time (producer/consumer split).

### 🔧 Shared Utilities
- **`macro/cache.py`** (simple, fan-in 4) — in-memory TTL cache used by both macro services.

### 🖼️ View Templates (Jinja2)
- **`templates/base.html`** ⚠️ **fan-in 8 (most-included)** — nav bar, slide-in freshness panel (`/api/freshness`), localStorage watchlist + context menu. *Every page extends it; implicit contract.*
- Pages: **`screener.html`** ⚠️ complex (1461 lines, default landing) · **`options.html`** ⚠️ complex (GEX view) · `stages.html` · `watchlist.html` · `chart.html` · `liquidity.html` · `macro.html` · `rrg.html`.
- Partials: `templates/macro/_liquidity` · `_layer_detail` · `_overlay` · `_transmission` · `_rrg`.

### ✅ Tests *(coverage gap — only the options corner)*
- `tests/test_gex_engine.py` (pure-math units) · `tests/test_gex_api.py` (Flask GEX endpoints, stubs `options_service`) · `tests/conftest.py` (sys.path).

## 2. Refactor hotspots (where to cut)

- **🔴 `app.py` (2090 lines) is the monolith.** It mixes routing + screener orchestration + classification loading + 7 feature areas. Everything below hangs off splitting this.
- **🟢 Two clean exemplars already exist — copy them:**
  - **Blueprint pattern** (`macro/__init__.py` → `routes.py` → `*_service.py` → `cache.py`): controller/service/utility separation. **Turn each feature (screener, options, watchlist, fundamentals) into its own blueprint** registered the same way.
  - **Orchestration-vs-pure-math** (`options_service.py` → `gex_engine.py`): messy I/O in a service, stateless math in an engine. Replicate when extracting logic from `app.py`.
- **11 files flagged `complex`:** stage_classifier, app, data_manager, update_classifications, gex_engine, options_service, both macro services, options.html, screener.html, data_freshness.
- **⚠️ Stable contracts to NOT break while refactoring:**
  - `data_manager`’s loaders (`load_prices`/`load_universe`/`load_spy`) — fan-in 7.
  - `base.html` template blocks + shared JS — fan-in 8; route/template couplings are implicit.
  - `update_classifications` JSON output schema — `app.py` reads it at request time.

## 6. Suggested refactor sequence (derived from the map)

1. **Add tests first** for screener + stage paths (mirror the GEX pattern) — lock behavior before moving code.
2. **Extract `screener_page` orchestration** from `app.py` into `screener.py` (service boundary; `app.py` only wires HTTP).
3. **Blueprint-ize each feature**: `screener_bp`, `options_bp`, `watchlist_bp`, `fundamentals_bp` — same shape as `macro/`. `app.py` shrinks to app-factory + blueprint registration.
4. **Make the port env-configurable** (`PORT`, default ≠ 5001) to end the energy-app collision.
5. **Add structured debug logging** (off by default) in `data_freshness` + `data_manager` so stale-data bugs surface.
